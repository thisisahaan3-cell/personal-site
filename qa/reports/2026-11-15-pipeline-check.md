## Findings about the pipeline
- `scripts/screenshot.mjs` reports "Failed to load resource ... 404" with no URL, so the failing asset cannot be identified from its output. Suggest logging `req.url()` and status from a `response` listener, as my script does.
- The same script's `requestfailed` listener does not fire on HTTP 404s. Only the console-error path catches them.
- It does not capture title, meta description, tab order or keyboard focus. These need separate scripts such as `qa/pipeline-check.mjs`.
- It runs three fixed 4.5s waits plus scrolling, so it is slow but works.
- `lsof` did not detect the listener here. Use `fuser PORT/tcp` for the stop step.
- The starter page's `public/` has only `Ahaan-Gupta-Resume.pdf`. The `next.svg` and `vercel.svg` files are gone, which is the source of the 404s. This is expected to disappear once the starter page is replaced.
